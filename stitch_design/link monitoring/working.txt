**Task: Build Broken Link Monitoring System (UI + Backend + Data Flow) for BuzzinBeats**

I want to build a complete Broken Link Monitoring system for BuzzinBeats where users can monitor Amazon, Flipkart, and custom links from their dashboard.

This should include:

* Frontend UI
* Backend logic
* Database structure
* Scheduled scanning system
* API/data flow to frontend
* Notifications when links fail

Build it as a scalable SaaS feature.

---

# 🎯 Objective

Create a system that automatically checks product links, stores results, and displays clean actionable data in the user dashboard.

Users should be able to:

* See healthy / warning / broken links
* Filter and search links
* View issue details
* Recheck links manually
* Receive alerts when links break

---

# 🧱 1. Database Requirements

Use existing tables where possible and modify current schema if needed.

## Product Links Data

Each product/link should store:

* id
* user_id
* page_id
* product_name
* store_type (amazon / flipkart / custom)
* product_url
* created_at
* updated_at

## Link Health Fields (add if missing)

* health_status (healthy / warning / broken)
* last_checked_at
* last_http_code
* response_time_ms
* failure_count
* last_error_message
* last_success_at

## Scan History Table (recommended)

Store every scan result:

* id
* product_id
* checked_at
* status
* http_code
* response_time_ms
* error_message

---

# ⚙️ 2. Backend Link Checker Logic

Create a background service / scheduled task that runs automatically.

## Schedule

Run:

* Daily minimum
* Better: every 6 hours
* Use queue/batch processing for scalability

## Scan Process

For each active product link:

### Step 1: Detect Store Type

* Amazon
* Flipkart
* Custom

### Step 2: Run Proper Check

## Amazon

Use Amazon API if configured.
If API unavailable, fallback to HTTP request.

Check:

* Page reachable
* Valid response
* Not removed

## Flipkart

Use HTTP request.

Check:

* Status code
* Redirect success
* Not product removed page (if detectable)

## Custom Links

Use generic URL health check:

* DNS resolves
* HTTP response
* Timeout
* Redirect loop
* SSL optional

---

# 🚨 3. Status Decision Rules

## Healthy

* HTTP 200
* Valid destination
* Fast response

## Warning

* Slow response
* Temporary redirect
* Rate limited
* One-time failure

## Broken

* 404
* 410
* Timeout repeatedly
* DNS fail
* Invalid URL
* Failed multiple scans

---

# 🔁 4. Failure Threshold Logic

Do not mark broken on one random failure.

Example:

* 1st failure = warning
* 3 consecutive failures = broken

Reset failure_count after successful scan.

---

# 🔔 5. Notification System

When status changes to broken:

## Notify User

* Email notification
* In-app dashboard alert

Include:

* Product name
* Page ID
* Store type
* Problem found
* Quick fix link

Avoid repeated spam notifications.

Send only on state change or after cooldown.
