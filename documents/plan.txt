You are working on the existing BuzzinBeats application.

IMPORTANT:
Do NOT rebuild the application from scratch.
Do NOT unnecessarily change the existing Product Management functionality.
First inspect the existing Laravel/PHP application, database schema, routes, controllers, models, Blade views/components, JavaScript, and existing admin/user dashboard before making changes.

The goal is to restructure the existing "Pages / Product Page" architecture into a more flexible CONTENT system.

============================================================
1. NEW CORE CONCEPT
============================================================

The application currently behaves as if every page is a Product Page.

That architecture must now change.

A BuzzinBeats public page should be treated as a:

CONTENT PAGE

A Content Page can contain one or more of these three independent content types:

1. Products
2. Redirect Links
3. Digital Products / Digital Content

A single Content Page must be able to contain:

- only Products
- only Redirect Links
- only Digital Products
- Products + Redirect Links
- Products + Digital Products
- Redirect Links + Digital Products
- Products + Redirect Links + Digital Products

Therefore these are NOT mutually exclusive page types.

They are CONTENT SECTIONS that can coexist on the same public page.

Example:

A user creates:

"CTET Preparation"

That page could contain:

SECTION 1:
Redirect → Rank Pulse website

SECTION 2:
Digital Product → CTET Practice Paper ₹49

SECTION 3:
Products → Recommended Amazon Products

The user must be able to control the order of these sections.

For example:

1. Redirect Links
2. Digital Products
3. Products

OR:

1. Products
2. Redirect Links
3. Digital Products

The order must be completely user-controlled.
